## 1. 背景与目标

当前系统已经形成多条展示方案主线：

1. Figma / System PDD 定义的全局壳层、导航、多标签工作区、右侧智能助手、底栏状态。
2. 当前维护页形成的树表维护模式，包括数据科目、产品科目、部门科目、部门预算科目和 BI 映射；报告科目维护入口已退休。
3. 预算管理页形成的输入、工作台、模板规则、智能预算模拟与模拟测算、预算输出闭环。
4. 费用模块形成的同步、导入、预测录入、执行报表闭环。
5. 多维分析形成的透视表、透视图、费用预算执行报表、预算展示报表。
6. 智能报告和智能 PPT 形成的模板上传、AI 识别、绑定配置、生成与质量检查路径。
7. Agent 形成的澄清、计划确认、透视建议、查询结果、历史会话等对话式展示。

这些方案各自成立，但页面密度、颜色语义、按钮层级、卡片边界、表格行为、空态和异常态尚未完全统一。本文目标是把它们收敛为一套可执行的展示语言，确保后续开发不是逐页“补丁式美化”，而是按同一产品系统推进。

## 2. 设计原则

### 2.1 银行预算系统气质

- UI 应服务于高频、长时间、数据密集的预算工作，整体气质为克制、稳定、清晰、可追溯。
- 首页和业务页面不采用营销式大卡片或装饰性视觉。首屏应直接进入工作状态。
- 信息密度应接近 Excel 和专业财务系统，但通过分组、冻结、层级、状态色降低认知负担。
- 页面文案应以业务任务为中心，不在界面中解释“本系统有什么功能”，除帮助页、空态和异常说明外不放教学式长文。

### 2.2 单一事实来源

- 任何页面展示的金额、口径、科目、产品、部门、版本，都必须能追溯到 Database PDD 定义的数据源。
- Figma、Excel 底稿、旧截图只作为界面样式和业务习惯参考，不作为主数据编码或持久化契约来源。
- 机构及产品数据录入、智能预算模拟与模拟测算、费用预测表、预算展示报表、透视分析必须共享 `budget_data` / `budget_summary` / `compare_budget_summary` 口径；产品维度配置统一进入“机构及产品”，产品指标配置统一进入“机构及产品指标”。

### 2.3 密度优先，层级清楚

- 默认页面采用“工具栏 + 主工作区 + 表格/树表”的业务软件布局。
- 需要上下文选择时，优先使用左树右表、三栏工作台、顶部紧凑筛选栏，不使用大面积说明卡。
- 卡片只用于独立对象、统计摘要、审核项、导入批次、质量报告、弹窗内容，不用于包裹整页。
- 表格优先保障冻结列、固定表头、横向滚动、键盘录入、空值语义和行级状态。

### 2.4 AI 辅助必须可确认

- Agent、智能报告、智能 PPT、AI 配置建议均应把 AI 输出作为建议或待确认项展示。
- 页面不得让 AI 输出直接成为正式预算计算、正式报告或正式 PPT，除非用户明确确认。
- AI 结果展示必须包含可解释依据：匹配来源、置信度、待确认项、质量检查、失败原因或生成参数。

## 3. 已有展示方案盘点

### 3.1 全局壳层

来源：`Banking_Budget_System_PDD.md`、`App.tsx`、`Header.tsx`、`NavigationTree.tsx`、`WorkArea.tsx`、`ChatBot.tsx`、`StatusBar.tsx`。

现状与统一方向：

- 顶栏展示软件版本、预算年份、版本号、用户和角色，是全局上下文，不应被业务页面重复大面积展示。
- 左侧导航按“预算管理 / 部门费用预算管理模块 / 多维分析工具 / 系统配置中心 / 帮助与使用说明”组织，权限过滤后展示可访问节点；机构及产品是产品维度和产品指标的唯一维护入口，规则配置台不再保留旧产品科目维护页。
- 中间工作区采用多标签页，适合并行处理多个预算任务。
- 右侧智能助手是常驻协作面板，可折叠、可扩大，承载 Agent 澄清和透视建议。
- 底栏展示数据库连接与全局计算刷新时间，应作为系统可信状态入口。

统一要求：

- 全局壳层保持三栏可调整结构：左导航、主工作区、右助手。
- 页面内部不得再自建全局导航或重复创建“智能助手”入口。
- 标签页标题使用左侧导航叶子名称；过长标题允许截断，但悬停展示完整名称。
- “智能分析报告”“智能演示PPT”是当前可打开入口，不再使用建设中灰态作为导航口径。

### 3.2 规则与主数据维护展示方案

来源：System PDD §4.2 至 §4.4、ZLC 产品层级补丁、当前 `OrgProductContent`、`OrgProductMetricContent`、`DataDepartmentContent`、`BudgetSubjectCatalogContent`。

页面族：

- 机构及产品。
- 机构及产品指标。
- 部门科目维护。
- 部门预算科目维护。

统一方向：

- 采用“树/目录 + 明细表 + 操作面板/弹窗”的统一模型。
- 主数据树表达业务层级，明细表表达可编辑字段。
- 机构及产品指标以“机构/产品 -> 指标表 -> 指标树”为主，不再恢复数据科目运行表独立页面。
- 产品编码由唯一指标号码前缀派生；回显必须展示 `AA` 微众银行或具体机构及产品主表编码，数据科目身份只由唯一指标号码表达。
- 机构及产品、部门、预算科目树的展开、选中、空态、禁用态应一致；预算展示配置不恢复旧报告科目维护页面，产品科目维护也不得作为第二入口恢复。

### 3.3 预算管理展示方案

来源：System PDD §0.9、§0.11、§0.14，当前 `OrgProductMetricContent`、`OrgProductDataEntryContent`、`BudgetActualBatchContent`、`BudgetSimulationContent`、`BudgetSimulationReverseContent`、`BudgetDisplayReportContent`。旧预算录入、旧 `DataAccountContent`、旧 `BudgetPredictionContent`、`ForecastWorkbenchContent`、`BudgetAssumptionContent` 和独立预测驱动输入页已物理删除；预算数、实际数和预测数唯一维护入口为 `OrgProductDataEntryContent`，指标配置唯一入口为 `OrgProductMetricContent`，情景测算进入智能预算模拟与模拟测算正算/倒算页面。

页面族：

- 机构及产品。
- 机构及产品指标。
- 机构及产品数据录入。
- 预算事实刷新跑批。
- 机构及产品指标。
- 机构及产品预测输出。
- 智能预算模拟与模拟测算（正算）。
- 智能预算模拟与模拟测算（倒算）。
- 费用执行明细导入。
- 预算展示报表。

统一方向：

- 预算管理按“配置 -> 输入 -> 输出”闭环组织。
- 产品维度配置进入“机构及产品”，产品指标配置进入“机构及产品指标”，不维护独立产品配置页面。
- 公式和预算规则配置收敛在机构及产品指标、公式编辑器、机构及产品数据录入和费用预测逻辑配置中，不恢复独立预算驱动维护页。
- 智能预算模拟与模拟测算正算/倒算作为产品维度情景测算页，读取机构及产品指标体系、数据科目运行绑定和年度预算事实；旧 `driver_*` 表和“驱动因素分组”不再作为展示或写入结构。
- 智能预算模拟与模拟测算作为情景输入与结果验证页，不应混入主预算输入页。
- 预算展示报表以 Excel 式报表为主，提供全行总表、分产品概览、单产品明细三类视图。

### 3.4 费用闭环展示方案

来源：Panpan 费用模块补丁、潘潘 0511 导出增强补丁、Codex 0511 数据同步规范补丁，当前 `DataSyncManagementContent`、`ExpenseActualImportContent`、`ExpenseForecastContent`、`ExpenseBudgetExecutionContent`。

页面族：

- 数据同步管理。
- 部门预算科目维护。
- 费用执行明细导入。
- 项目/费用预算输入。
- 费用预算执行报表。

统一方向：

- 费用模块以“框架初始化 / 实际导入 / 预测录入 / 执行分析 / Excel 导出”为闭环。
- 数据同步管理是历史初始化和批量导入总控台，不应替代日常主数据维护。
- 费用执行明细导入采用“文件选择 -> 预览 -> 未匹配预警 -> 写库 -> 批次记录”的固定流程。
- 费用预测表采用高密度月度表格，支持主体、事业群、费用归属部门三种视角，只有可编辑口径显示输入态。
- 费用预算执行报表保留查询模式和模板模式，但筛选栏、单位切换、导出按钮、空态和异常态需与预算展示报表一致。

### 3.5 多维分析展示方案

来源：System PDD §4.5、Agent PDD 透视建议章节、`PivotTableContent`、`PivotChartContent`、`ExpenseBudgetExecutionContent`、`BudgetDisplayReportContent`。

页面族：

- 当前可编辑年度多版本透视报表。
- 多年度对比透视报表。
- 多年度数据透视图。
- 费用预算执行报表。
- 预算展示报表。

统一方向：

- 两个透视表入口保持相同交互模型，仅数据源和可编辑性不同。
- 多年度数据透视图作为透视结果的可视化消费层，图表筛选、单位、展示模式应与透视字段设置同源。
- Agent 推荐透视视角应能一键打开多年度对比透视，并保留搜索预填。
- 分析页以“筛选栏 + 分析视图 + 导出/刷新工具”为统一骨架。
- 图表页避免装饰化视觉，优先表达图表类型、口径、单位、筛选条件和数据为空原因。

### 3.6 智能报告与智能 PPT 展示方案

来源：`.scratch/smart-report-ai-blueprint/PRD.md`、`.scratch/ai-ppt-template-studio/PRD.md`、当前 `AnalysisReportContent`、`AnalysisPPTContent`。

页面族：

- 智能分析报告。
- 智能演示PPT。
- AI 智能报告蓝图。
- AI PPT Template Studio。

统一方向：

- 智能报告主方向从“手工占位符模板编辑”收敛为“AI 报告结构理解 + 可刷新报告蓝图”。
- 智能报告页面使用“模板/报告库 + AI 识别结果 + 待确认项审核台 + 生成参数 + 预览/导出”的流程。
- 智能 PPT 主方向保留场景生成，同时新增模板驱动能力：模板库、绑定工作区、生成中心、质量/修订视图。
- PPT 模板绑定工作区采用三栏：缩略图导航、页面对象列表、绑定规则配置。
- 质量报告作为一等展示对象，统一列出缺失数据、未绑定对象、图表刷新状态、文本溢出风险和人工确认项。

### 3.7 Agent 助手展示方案

来源：Agent PDD、当前 `ChatBot.tsx`。

展示对象：

- 欢迎语与通用回答。
- 澄清问题与候选项。
- 已锁定查询维度。
- 规划确认与下一步按钮。
- 管衡推荐透视视角卡片。
- 查询结果表格。
- 历史会话与模板。
- 满意/不满意反馈。

统一方向：

- Agent 面板保持紧凑对话体验，不承担复杂表格的长期分析工作区。
- “已锁定查询维度”使用紧凑区块，避免重复空行。
- 透视建议只在“管衡推荐透视视角”卡片展示，不在正文重复。
- 查询结果表格只做快速预览，深入分析引导到透视表、透视图、智能报告或预算展示报表。
- 操作按钮使用明确动词，按钮数量保持克制，优先呈现最相关下一步。

## 5. 页面骨架规范

### 5.1 标准业务页

适用：主数据维护、配置、输入、同步、报表查询。

结构：

1. 页面标题行：标题、加载状态、主操作按钮。
2. 紧凑筛选/工具栏：年份、版本、口径、产品、部门、单位、搜索、刷新、导入、导出。
3. 主工作区：树表、普通表、报表、三栏工作台或预览区。
4. 辅助反馈：状态条、错误提示、空态、批次记录、质量报告。

要求：

- 标题高度固定，文字使用 14px 至 16px，不使用巨型标题。
- 工具栏优先横向排列，可换行但不遮挡主表。
- 页面主区域必须 `min-height: 0` 并允许内部滚动，避免整页滚动导致表头和操作区丢失。

### 5.2 三栏工作台

适用：PPT 模板绑定、复杂规则配置、审核台类页面。

结构：

- 左栏：对象导航，如产品树、模板缩略图、配置目录。
- 中栏：主要工作表、页面对象、试算结果。
- 右栏：当前选中对象的摘要、规则、状态、AI 建议。

要求：

- 左栏宽度 240px 至 320px，右栏宽度 300px 至 420px。
- 中栏为主工作空间，不放解释性说明卡。
- 右栏只展示当前上下文，不做全局导航。

### 5.3 表格与报表页

适用：预算输入、智能预算模拟与模拟测算、费用预测、费用执行报表、透视表、预算展示报表。

要求：

- 表头固定，关键识别列固定。
- 数字右对齐，文本左对齐，层级列保留缩进和展开图标。
- 可编辑单元格、只读单元格、公式锁定单元格、缺失值必须有稳定视觉区分。
- 空值语义统一：只读缺失显示 `-`；可编辑缺失显示为空输入态；计算失败显示异常标记并提供原因。
- 金额单位切换必须影响页面与导出结果，且显示当前单位。
- 导出文件口径必须与页面当前筛选条件一致。

### 5.4 弹窗与抽屉

适用：导入预览、公式编辑、产品多选、规则配置、AI 待确认项。

要求：

- 大型配置任务使用宽弹窗，不挤在右侧小面板里。
- 弹窗页脚固定，主操作在右侧，取消/返回在左侧或主操作左边。
- 弹窗内表格仍需固定表头和内部滚动。
- 不在弹窗中再嵌套卡片式页面区块。

## 6. 视觉与组件规范

### 6.1 色彩语义

建议统一为以下语义，不逐页新增随意色：

| 语义 | 用途 |
|------|------|
| 中性灰 | 页面背景、边框、表头、普通按钮、只读区域 |
| 专业蓝 | 主操作、当前选中、链接、聚焦态 |
| 绿色 | 成功、已完成、可用、导入匹配 |
| 琥珀色 | 警告、待确认、建设中、部分成功 |
| 红色 | 错误、失败、危险操作 |
| 紫色/靛蓝 | 仅用于 Agent / AI 建议类卡片，避免扩散到普通业务页 |

要求：

- 主背景以白色和浅灰为主，避免大面积蓝色、紫色或渐变。
- 业务页不使用装饰性渐变、光斑、插画背景。
- 状态色应同时配合文字或图标，不能只靠颜色表达。

### 6.2 字体与密度

- 全局字号以 12px、13px、14px 为主。
- 页面标题 14px 至 16px；表格正文 12px；辅助说明 11px 至 12px。
- 按钮高度 28px 至 32px；表格行高 28px 至 36px，按页面密度选择。
- 不使用视口宽度缩放字号。
- 财务数字优先使用等宽或表格数字特性，便于纵向比较。

### 6.3 按钮层级

| 层级 | 用途 | 样式 |
|------|------|------|
| Primary | 保存、导入、生成、下发并试算、执行查询 | 蓝底白字 |
| Secondary | 刷新、下载模板、预览、复制、打开记录 | 白底灰边 |
| Success | 导入成功确认、生成可下载、同步完成 | 绿底或绿边 |
| Warning | 待确认、继续但有风险 | 琥珀色弱强调 |
| Danger | 删除、清空、覆盖确认 | 红色，仅在确有破坏性时使用 |

要求：

- 同一工具栏最多一个 Primary。
- 图标按钮必须有 `title` 或 tooltip。
- 只有明确命令才使用文字按钮，常见工具操作优先使用 lucide 图标加 tooltip。

### 6.4 卡片使用边界

允许使用卡片的场景：

- 导入批次、质量检查项、AI 待确认项、统计摘要、小型对象列表项。
- 弹窗中的独立选择对象。

不应使用卡片的场景：

- 整个页面外框。
- 页内大区块互相包裹。
- 表格外再叠多层阴影卡片。

卡片圆角不超过 8px；业务表格和工具栏圆角可更小。

## 7. 交互状态规范

### 7.1 加载态

- 页面首次加载显示骨架或紧凑加载文字。
- 表格局部刷新不遮挡整个页面，除非操作会改变整页数据。
- Agent 流式处理中展示阶段进度，但不占用大量垂直空间。

### 7.2 空态

空态必须说明当前为空的原因和下一步：

- 无主数据：提示去对应维护页或导入。
- 无筛选结果：提示调整筛选条件。
- 无权限：提示联系管理员，不展示灰掉但可误操作的表单。
- 未选择对象：在右侧主区显示“请选择末级产品/模板/节点”，不加载无意义表格。

### 7.3 错误态

- API 错误显示可读业务原因，不展示原始堆栈。
- 导入失败必须返回行列级原因，并支持下载回写结果文件。
- AI 失败必须区分模型不可用、解析失败、匹配不足、生成失败。

### 7.4 建设中与灰态

- 灰态入口只用于“可点击但能力未完全上线”的页面。
- 灰态页面打开后必须有明确提示、已完成能力和下一步状态，不应空白。
- 权限禁用和建设中灰态必须视觉区分。

## 8. 分页面统一要求

### 8.1 机构产品指标运行引用

- 旧数据科目运行表独立页面已下线；主交互收拢到机构及产品指标，后端运行引用仅用于公式、预算事实和读模型查询。
- 产品编码回显使用业务语言，不直接裸露逗号编码串作为主要显示。
- 公式编辑器、指标选择、产品多选在所有相关页面复用同一交互。

### 8.2 机构及产品指标

- 默认以机构及产品主表和产品前缀指标树节点为主，产品维度通过机构及产品树、产品编码列和状态视图表达。
- 唯一指标号码由产品前缀指标主键生成，不允许通过旧产品科目维护或旧数据科目运行表单独生成临时数据科目。
- 不保留产品预算组件、待补齐指标或转正中间表；产品维度指标只能写入“机构及产品指标”，再同步为机构产品指标运行引用。
- AI 配置建议只能进入机构及产品指标草稿，用户确认后才允许写入公式、引用配置、影响范围和校验结果。

### 8.3 智能预算模拟与模拟测算与情景因子输入

- 产品候选来自当前机构及产品主表展开的运行产品清单；贷款类情景因子按当前页面规则筛选，不从旧驱动表读取。
- 情景参数表只展示当前智能预算模拟与模拟测算支持的指标和产品组合，基准值读取机构及产品指标体系、机构产品指标运行绑定和年度预算事实。
- 默认突出当前可编辑年度的基准情景和模拟情景；历史预算、实际值或对比口径只能作为只读上下文进入当前读模型。
- 编辑通过智能预算模拟与模拟测算 Interface 生成情景结果，不创建独立预测驱动数据表，也不恢复 `driver_*` 私有表。

### 8.4 费用预测表

- 视角切换为主体、事业群、费用归属部门。
- 费用归属部门口径支持录入和导入，其他口径以汇总展示为主。
- 经营分析列与月度列并列展示时，需要清晰分组表头。
- 导出结果必须保留当前金额单位和可计算公式。

### 8.5 预算展示报表

- 顶部筛选栏包含年份、预算基准、预测版本、产品筛选、单位。
- 默认展示全行总表，分产品概览和单产品明细作为同级页签。
- 行项目以 `budget_output_display_item` 展示配置、机构及产品指标体系和机构产品指标运行引用为准，不硬编码 Excel 底稿行，也不恢复旧报告科目树。
- 月度明细列允许展开收起，避免默认过宽。

### 8.6 智能分析报告

- 主流程为上传或选择 Word 报告 -> AI 识别 -> 异常项审核 -> 参数选择 -> 预览 -> 导出。
- 高置信度自动通过，低置信度和未匹配项进入待确认审核台。
- 分析任务必须展示业务可读执行计划，不展示原始 JSON 或 SQL。
- 生成前阻断未解决的关键待确认项。

### 8.7 智能演示PPT

- 保留场景生成和模板驱动两个模式，但导航和页面文案需清楚区分。
- 模板驱动模式以模板库、绑定工作区、生成中心、质量报告组织。
- 绑定工作区三栏展示缩略图、对象列表、规则配置。
- 生成结果必须展示质量报告，用户可据此决定下载、修订或重生成。

### 8.8 Agent 智能助手

- 对话答案保持紧凑，复杂分析落到主工作区。
- 透视建议卡片独立展示解释、置信度和打开入口。
- 历史会话弹窗采用左列表右预览。
- 满意/不满意反馈保持轻量，不中断当前工作流。

## 9. 组件化落地建议

建议在 `apps/web/src/app/components` 逐步沉淀以下共享组件，降低页面风格漂移：

| 组件 | 用途 |
|------|------|
| `PageShell` | 标准页面标题、工具栏、主区、状态区 |
| `PageToolbar` | 筛选、搜索、刷新、导入、导出按钮统一排列 |
| `DataGridShell` | 固定表头、固定列、空态、错误态、加载态 |
| `TreePane` | 左侧树导航、展开、选中、搜索、空态 |
| `StatusBanner` | 成功、警告、错误、信息提示 |
| `MetricUnitSelector` | 金额单位、百分比、户数等单位切换 |
| `ImportFlowDialog` | 下载模板、上传、预览、导入、结果下载 |
| `AiReviewPanel` | AI 待确认项、置信度、采纳/替换/忽略 |
| `QualityReportPanel` | 报告/PPT 生成质量检查结果 |
| `WorkbenchLayout` | 左中右三栏工作台骨架 |

落地顺序建议：

1. 先统一全局 token、按钮、提示、表格基础类。
2. 再抽 `PageShell`、`PageToolbar`、`DataGridShell`，覆盖高频业务页。
3. 最后统一复杂工作台和智能报告/PPT 的 AI 审核组件。

## 10. 验收标准

### 10.1 页面一致性

- 所有业务页都有一致的标题行、工具栏、加载态、空态、错误态。
- 主操作按钮颜色和位置一致，危险操作有二次确认。
- 表格表头、边框、行高、数字对齐、冻结行为在同类页面一致。
- 页面不出现互相嵌套的大卡片，不出现装饰性渐变背景。

### 10.2 业务一致性

- 同一数据在预算输入、智能预算模拟与模拟测算、预算展示、透视、智能报告中口径一致。
- 单位切换后页面、导出、质量报告口径一致。
- 实际数和历史口径只读，当前预算可编辑范围清晰。
- AI 建议、草稿、正式下发三者状态可区分。

### 10.3 可用性

- 1024px 宽度下仍可完成基础查询和表格查看。
- 1366px 宽度下标准业务页无需横向滚动整个页面，只在表格内部横向滚动。
- 高密度表格支持键盘录入，不因 hover、编辑、加载导致列宽跳动。
- 长中文标题、长科目路径、长产品名不溢出按钮或表格头。

### 10.4 回归检查

- `npm run build` 通过。
- 核心页面在浏览器中检查：导航、标签页、表格滚动、弹窗、导入流程、右侧助手。
- 至少覆盖以下页面截图或人工走查：机构及产品、机构及产品指标、智能预算模拟与模拟测算正算/倒算、费用预测表、费用预算执行报表、预算展示报表、智能分析报告、智能演示PPT、Agent 助手；数据科目仅通过库存门禁、后端运行读模型和只读导出校验，不作为独立页面走查对象。

## 11. 分阶段实施计划

### 阶段一：统一视觉底座

- 梳理 `theme.css`、`index.css` 与 Tailwind 常用类，固化颜色、字号、圆角、边框、按钮密度。
- 统一全局壳层背景、导航选中态、标签页样式、右侧助手边界。
- 先不重构业务逻辑，只做低风险样式归一。

### 阶段二：统一标准业务页

- 抽取 `PageShell`、`PageToolbar`、`StatusBanner`。
- 优先覆盖数据同步管理、费用执行明细导入、用户权限管理、预算展示报表等结构较清晰页面。
- 建立空态、错误态、加载态规范。

### 阶段三：统一表格与树表

- 抽取或规范 `DataGridShell`、树表行、冻结表头、单位切换、导出按钮。
- 覆盖预算输入、智能预算模拟与模拟测算、费用预测、费用预算执行报表、透视表。
- 补齐可编辑、只读、公式锁定、缺失值和异常单元格状态。

### 阶段四：统一复杂工作台

- PPT Template Studio、智能报告审核台采用统一三栏或审核台骨架；产品维度数据科目配置不再作为单独 UI 骨架目标。
- AI 建议和质量报告组件统一。
- 草稿、待确认、已下发、生成成功、生成失败的状态样式统一。

### 阶段五：文档合并与验收固化

- 将本文经过评审的条款合并进 System PDD 对应章节。
- 给 CHANGELOG 增加 UI 统一改造记录。
- 建立人工走查清单和截图基线，作为后续合并包验收的一部分。
