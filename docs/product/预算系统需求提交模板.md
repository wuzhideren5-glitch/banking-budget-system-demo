# 预算系统需求提交模板

本文档用于帮助快速、准确地描述需求，减少来回确认成本，提高沟通效率。

适用场景包括但不限于：
- 页面展示调整
- 报表口径修改
- 主数据维护
- Excel 导入/导出规则调整
- 树形层级结构调整
- 新增维度或筛选条件
- 旧口径删除、归档或按当前模型重建

## 一、填写原则

提交需求时，优先写清以下 3 件事：

1. 当前是什么
2. 你希望改成什么
3. 这是只改展示，还是要改到底层数据

如果时间紧，至少把上面 3 点讲清楚。

## 五、最推荐优先写清楚的内容

以后提需求时，最建议优先补充以下内容：

### 1. 这是哪个页面的问题
- 报表页
- 设置页
- 导入页
- 导出结果
- 底层主数据

### 2. 你要改哪一层
- 只改页面显示
- 改接口
- 改主数据
- 改数据库结构

### 3. 数据来源是什么
- Excel 文件
- 数据库表
- 当前系统已有页面
- 多个来源混合

### 4. 层级应该怎么排
例如：
- 主体 -> 事业群 -> 部门 -> 产品
- 事业群 -> 费用归属部门 -> 科目

### 5. 新旧口径冲突时如何处理
例如：
- 旧结构删除
- 旧数据按当前模型重建后导入
- 旧文件仅作为人工核对来源，不进入运行链路

### 6. 最终怎么验收
例如：
- 页面应看到哪些字段
- 导出应是什么顺序
- 哪几个典型例子必须正确

## 六、适合直接复制的一句话模板

如果你时间很紧，也可以直接按这句话发：

```md
请把【当前结构】从 xxx 改成 xxx；
影响范围是【页面/接口/导出/主数据】；
数据来源是 xxx；
旧口径【删除/归档/按当前模型重建】；
验收时我要看到 xxx。
```

## 七、示例

### 示例 1：层级调整

```md
需求：部门科目维护调整层级
当前：页面按部门树直接展示，主体只是标签
期望：主体作为第一级，事业群作为第二级，部门作为第三级
涉及页面：部门科目维护
数据来源：dept_account；产品维度来自“机构及产品”主表，运行查询读取由主表展开的运行产品清单；历史框架文件仅允许通过显式导入形成内部数据
影响范围：页面展示 + 导出
旧口径处理方式：删除旧部门-产品映射，不再用部门树推断产品
验收标准：页面和导出都显示为“主体 -> 事业群 -> 部门”；产品选择使用“机构及产品”树
例子：科技子必须作为一级节点，不应挂在虚拟部门下面显示
```

### 示例 2：报表维度调整

```md
需求：费用预算执行报表增加主体维度
当前：只支持事业群和费用归属部门
期望：增加主体维度，主体区分为微众银行、科技子、科技孙
涉及页面：费用预算执行报表
数据来源：部门科目维护、部门预算科目维护、费用执行上传导入后的内部表、预算数据表
影响范围：报表查询 + 导出
旧口径处理方式：预算部门维度不进入当前查询和导出链路
验收标准：报表支持按主体查询和导出
例子：科技孙在主体维度下应能单独统计
```

### 示例 3：设置页与报表口径一致

```md
需求：设置页和报表主体口径统一
当前：报表有主体，设置页没有
期望：设置页也显示主体，并和报表口径一致
涉及页面：部门科目维护、费用预算执行报表
数据来源：当前部门树 + 框架映射
影响范围：接口返回 + 页面展示
旧口径处理方式：旧节点清理或归档，不再进入当前页面和运行链路
验收标准：同一个部门在报表和设置页看到的主体一致
```

## 八、结论

最有效的需求描述方式，不是一次性写很多话，而是优先明确：

1. 当前是什么
2. 想改成什么
3. 改展示还是改底层
4. 数据从哪里来
5. 旧逻辑怎么处理
6. 你用什么标准验收

只要这 6 点写清楚，后续沟通效率会明显提高。
