## 1. 文档定位

- 本文是 Agent 设计细节的唯一落地文档（单一事实来源）。
- 当前版本已纳入用户截至目前全部确认需求，后续开发按本文执行。
- `System PDD` 保留宏观架构，具体实现细节与验收规则以本文为准。
- 数据口径与安全边界仍受 `Rules PDD`、`Database PDD` 约束。

---

## 2. 产品目标与边界

### 2.1 产品目标

1. 对预算分析请求形成闭环：意图识别 -> 澄清 -> 规划 -> 执行 -> 反馈 -> 记忆沉淀。
2. 对通用问题提供有质量且有温度的回答，不“机械拒答”。
3. 支持“SQL 查询 + 双透视入口”协同，用户可选择其一或两者并行。
4. 在预算分析场景中，Agent 可主动推荐透视视角和字段布局。

### 2.2 产品边界

- 预算相关：允许只读查询、结果解释、透视建议与透视配置建议。
- 非预算相关：可通用回答，并提示预算专长范围。
- 写库操作：当前阶段不开放，后续必须显式确认 + 审计。

### 2.3 免费开源约束

- 优先免费开源与浏览器原生方案。
- 文件解析、语音、OCR 采用本地或开源依赖实现。
- 可接入大模型用于质量增强（如 DeepSeek），但需可降级到本地规则与模板。

## 3. Agent 人设与回复策略

### 3.1 人设

- 名称：管衡。
- 身份：预算部门数字员工。
- 风格：专业、亲切、可协作，不端着、不生硬。

### 3.2 首条欢迎语要求

- 必含：身份说明、能力说明、提问引导（时间范围/业务对象/对比方式/粒度）。

### 3.3 通用问题回复策略

- 先尽力回答，再提醒预算专长边界。
- 回答长度控制：相比原始长回答截断约一半，避免“炫技式”冗长。
- 语气要求：自然、温暖、有执行建议。

### 3.4 不满意反馈策略

- 先致歉与安抚，再发起二次澄清并支持重跑。

### 3.5 输出语言规则

- 用户可见输出默认中文。
- 禁止向用户直接展示 SQL 原文。
- 用户可见字段名必须中文化。

## 4. 意图识别与路由策略（关键）

### 4.1 意图类型

- `budget`：预算/财务数据查询分析与执行链路。
- `general`：通用问答、闲聊、预算知识泛问（不含具体数据分析）。

### 4.2 分层识别架构

1. **规则层**：关键词、上下文承接、执行口令、布局调整等。
2. **语义层**：轻量 semantic 相似度（字符 n-gram）用于兜底。
3. **仲裁层**：灰区时使用 LLM 仲裁（可配置开关）。
4. **可观测层**：路由 trace 持久化到 `intent_router_trace.jsonl`。

### 4.3 预算域词库要求

- 强词与弱词双层词库，覆盖银行预算领域高频词：
  - 预算、实际、预实、收入、利息、费用、利润、拨备、NIM、ROE；
  - 部门、产品、科目、支行、贷款、存款、资产、负债；
  - 月度、季度、年度、同比、环比、趋势、报表、明细、汇总、模拟等。
- 词库需在代码词库与 `synonyms_seed.csv` 中保持一致维护。

### 4.4 上下文继承与防误继承

- 新主题默认不继承历史槽位（避免“汽车金融业务怎么样”直接套用旧口径）。
- 仅以下场景允许继承：补充条件、上下文承接短句、明确执行口令、布局调整口令。
- `inherit_history_slots` 为显式控制开关。

### 4.5 特殊行为要求

- 元数据统计类（如“多少个部门”）可直接执行。
- 简短确认语（如“好的”）仅在存在待执行预算计划时触发执行。
- 对“把这些部门列出来”类请求必须识别为预算上下文跟进，不得回退通用问答。

## 5. 状态机与主流程

```text
UserInput
  -> intent_router
    -> general_answer (if general)
    -> kb_context -> requirement_check (if budget)
      -> clarify (slots missing && not execute)
        -> services/agent_compare_clarification.py handles compare L1-L5 version clarification
      -> plan_query
        -> services/agent_pivot_suggestion.py generate reply_options (SQL / Pivot / Both)
        -> optional pivot_suggestion
      -> execute_query (if wants_execute)
      -> save_memory
```

### 5.1 澄清槽位

- 时间范围 `time_period`
- 同比版本 `comparison_version`：由 `apps/api/app/services/agent_compare_clarification.py` 生成 L1-L5 compare 版本选项，并写入 `pending_query_spec.__require_compare_level__` / `__selected_compare_level__`。
- 业务对象 `business_scope`
- 对比方式 `comparison_type`
- 分析粒度 `granularity`

### 5.2 澄清交互

- 返回缺失项 + 候选按钮分组。
- 支持“发送已选条件”与“按默认执行”。
- 用户输入文本时自动拼接已选条件，减少漏点发问成本。

### 5.3 计划阶段强制提示

- 查询规划回复必须包含确认提示：
  - “请回复‘确认执行’后开始执行查询。”

### 5.4 问询链路详细设计（讲解版）

本节定义“用户提问 -> 口径确认 -> 可执行计划 -> 执行”的可复述流程，作为演示与验收主线。

#### 5.4.1 流程分层

1. **意图路由层**：识别 `budget/general`，预算类进入问询链路。
2. **需求规格层**：沉淀 `query_spec`（时间、部门、产品、标准指标树节点/数据科目、粒度等）。
3. **缺失澄清层**：若关键槽位缺失，返回 `need_clarification=true` 与候选项。
4. **方案确认层**：输出“已锁定维度 + 计划说明 + 执行提示 + 操作选项”。
5. **执行层**：收到“确认执行/按默认执行/按当前口径重跑”等口令后执行只读 SQL。
6. **沉淀层**：写入短期会话状态与长期记忆（反馈闭环）。

#### 5.4.2 查询规格 `query_spec` 的职责

- `query_spec` 是问询阶段的唯一口径对象。
- 任何对外展示的“锁定条件”必须来自 `query_spec`，不得在文案中拼接冲突科目名。
- `query_spec` 常见维度：
  - `metric_nodes`（标准指标树 node_code/name）
  - `data_accounts`（数据科目 code/name）
  - `departments`（部门 code/name）
  - `products`（产品 code/name）
  - `period_description` / `year` / `quarter` / `month`

#### 5.4.3 “已锁定的查询维度”展示规范（当前实现）

- 标题固定：`## 已锁定的查询维度（系统内 code｜name）`。
- 区块顺序固定：标准指标树节点 -> 数据科目 -> 部门科目 -> 产品科目 -> 时间范围。
- 每个区块使用紧凑列表展示，不插入额外空白段落。
- 无值时显示 `- （未指定）`。
- 不再追加“以下规划与执行须与上述代码一致...”结尾句（避免重复提示）。

#### 5.4.4 方案确认消息构成（用户可见）

确认阶段回复由以下部分组成（按顺序）：

1. `已锁定的查询维度` 区块（如存在）。
2. 规划正文（查询上下文、口径说明、下一步建议）。
3. 固定执行提示：`请回复“确认执行”后开始执行查询。`
4. 选项按钮区（`reply_options`）：执行 SQL / 打开透视表 / 两者都做。
5. 透视建议卡片（若推荐）：由 `pivot_suggestion` 在前端渲染。

#### 5.4.5 去重与一致性规则

- **锁定维度区块去重**：若 LLM 改写中重复注入同标题区块，仅保留第一段。
- **透视说明去重**：后端正文不再拼接“透视建议：...”，防止与卡片重复。
- **确认提示保底**：若改写结果未包含“确认执行/开始执行查询”语义，系统自动追加确认提示。

#### 5.4.6 前端交互约定（问询场景）

- 澄清消息可通过候选按钮拼装条件；支持“发送已选条件”“按默认执行”。
- 规划消息展示“管衡建议的下一步”按钮组：
  - `确认执行`（只读 SQL）
  - `打开数据透视表`
  - `同时打开数据透视表并执行`
- “管衡推荐透视视角”卡片独立展示 `pivot_suggestion.explanation` 与置信度。

#### 5.4.7 异常与防错

- 维度一致性校验失败时，必须中止执行并提示缺失维度项。
- 无可执行 SQL 时，回复“当前没有可执行 SQL，请先完成查询规划。”
- 任何执行都必须受只读护栏（见 §6.1）约束。

### 5.5 关键问询状态字段（后端）

- `need_clarification`：是否仍需用户补槽位。
- `missing_slots` / `clarification_options`：缺失项与候选值。
- `pm_query_spec`：当前已锁定查询规格。
- `reply_options`：前端可操作按钮集合。
- `pivot_suggestion`：透视字段建议与解释。
- `wants_execute`：是否进入执行分支。

### 5.6 关键问询状态字段（前端）

- 消息维度：`role`、`content`、`needClarification`、`replyOptions`、`pivotSuggestion`。
- 交互维度：澄清项本地选择状态、历史恢复状态、发送中状态。
- 透视联动维度：点击按钮后调用 `onOpenPivotTable(suggestion)`，并在需要时叠加“确认执行”。

### 5.7 讲解演示建议脚本（用于培训）

建议按以下话术演示：

1. 用户输入含糊需求（如“看下汽车金融营业收入”）。
2. 演示系统如何补齐时间/口径并展示“已锁定的查询维度”。
3. 演示三种动作按钮差异（SQL、透视、两者都做）。
4. 演示“管衡推荐透视视角”卡片和透视页自动应用效果。
5. 演示“确认执行”后结果预览与反馈闭环。

### 5.8 当前验收重点（问询相关）

- 锁定维度展示紧凑，无冗余空行。
- 透视说明只出现一次（卡片）。
- 确认消息始终带执行提示。
- 对比透视搜索框正确预填 `pivot_search_text`。
- 回复按钮触发行为与文案一致。

### 5.9 不纳入本期的问询能力

- 自动改写用户口径并直接写库（仍禁止）。
- 多轮复杂冲突消解的可视化 diff 审批流（留在后续版本）。
- Agent 对“智能分析报告 / 智能演示PPT”结果页的一键自动编排与跨页生成控制不纳入本期问询能力；两页本身已是当前可打开入口，分别通过 `smartReportApi.ts` 与 `smartPptApi.ts` 调用现有生成、预览、刷新和下载接口。

## 6. SQL 执行与结果输出规范

### 6.1 只读护栏

- 仅允许 `SELECT` / `WITH`。
- 禁止 DDL / DML / 多语句。
- 白名单表 + 默认 `LIMIT`。

### 6.2 生成策略

- 元数据类支持 `COUNT DISTINCT` 与 `SELECT DISTINCT` 列表模式。
- 支持预算/实际双列展示（中文别名：`预算值`、`实际值`）。

### 6.3 结果展示规范

- 聊天中显示中文字段预览表与中文分析说明。
- 若数据缺失或口径异常，需给出数据质量说明与下一步建议。

## 7. 透视表协同能力（新增关键章节）

### 7.1 用户选项能力

在规划阶段，面向预算分析类问题，Agent 可返回：

1. 执行只读 SQL 查询；
2. 打开 **数据透视表-当前年度多版本透视**；
3. 打开 **数据透视表-多年度对比透视**；
4. 两者都做（执行 SQL + 打开所选透视表）。

### 7.2 透视偏好继承

- 用户明确提过“透视表/Pivot”后，后续执行链路应保留偏好。
- 即使用户后续只说“确认执行”，也应自动打开透视表页签（分析类）。

### 7.3 主动透视建议（用户未主动提透视表）

- Agent 基于需求自动判断是否推荐透视：
  - 趋势、同比/环比、多维对比、预算/实际拆解、部门/产品/科目拆分场景优先推荐。
- 透视推荐由 `apps/api/app/services/agent_pivot_suggestion.py` 统一生成；`agent_graph.py` 只在规划/执行节点调用该 Module，不直接拼装前端 DTO。
- 返回结构化建议 `pivot_suggestion`：
  - `row_field_ids`
  - `column_field_ids`
  - `page_field_ids`
  - `value_field_ids`
  - `page_selections`
  - `explanation`
  - `confidence`
  - `pivot_search_text`（仅指标树节点或数据科目 code）

### 7.4 前端一键应用透视建议

- 用户点击“打开透视表”或“两者都做”时：
  - 若为当前年度场景，打开 `analysis-pivot-table-current` 页签；
  - 若为多年度对比场景，打开 `analysis-pivot-table-compare` 页签；
  - 同步写入透视配置；
  - 透视页即时应用建议字段（行/列/页/值与页筛选）。
- **`pivot_search_text` 应用规则**：
  - 当前年度透视：写入搜索框并立即生效；
  - 多年度对比透视：同样写入搜索框，不得被 compare 分支清空；
  - `pivot_search_text` 仅承载标准指标树节点或数据科目 code，多关键词按空格 OR 过滤。
- **展示去重规则**：透视说明统一在“管衡推荐透视视角”卡片显示，确认正文不再重复。

## 8. 记忆与会话管理

### 8.1 短期记忆

- 当前会话消息、澄清状态、执行计划、透视偏好、回复选项。

### 8.2 长期记忆

- 存储位置：`resources/knowledge_base/03_conversation_memory/memory_runtime.jsonl`。
- 记录最终需求、澄清轮次、执行结果元信息、满意度反馈。

### 8.3 会话持久化（前端）

- 折叠/展开聊天面板不应重置会话。
- 聊天进行中折叠再展开不应中断运行。
- 历史会话需展示：
  - 会话主题
  - 首次对话时间
  - 最后对话时间
  - 消息条数
- 点击历史会话可恢复并继续原会话。

## 9. 聊天窗口与六按钮规格（最终版）

### 9.1 智能问答模板

- 模板数量 >= 10，支持编辑、润色、发送。
- 模板弹窗全屏级尺寸，避免变形。

### 9.2 上传文件

- 支持 txt/doc/docx/md/excel/html/pdf/图片。
- 返回摘要、关键点、建议动作、解析提示。

### 9.3 语音输入

- 语音输入应持续至用户手动停止（避免短暂停顿自动结束）。
- 录音中按钮显示闪烁语音波图标。

### 9.4 电话聊天

- 语音输入 + TTS 播报；支持打断播报。

### 9.5 历史

- 弹窗展示历史会话与会话预览；
- 可一键恢复到原会话继续对话。

### 9.6 重跑

- “按当前口径重跑”直接触发执行链路。

### 9.7 统一体验要求

- 聊天发送中显示旋转加载提示，转速约 7 秒周期。
- 模态窗口统一大尺寸、可读性优先。
- 所有按钮需有 tooltip。
- 新消息自动滚动到底部。

---

## 10. 透视表页面体验要求

- 在工具切换期间保留透视配置（行/列/页/值、合计开关、页筛选）。
- Agent 下发透视建议时，透视表应立即应用配置。
- 透视配置应兼容本地持久化，避免重复配置成本。
- 多年度对比透视在应用建议后应保留搜索框预填 code（用于快速收敛到锁定科目）。

## 11. 本地开源技术路线

### 11.1 前端

- React + TypeScript + Tailwind
- `react-resizable-panels`
- Web Speech API + `speechSynthesis`

### 11.2 后端

- FastAPI + LangGraph
- SQLite + `aiosqlite`
