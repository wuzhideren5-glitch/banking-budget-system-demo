# 银行业务预算系统前端设计规范

| 项目 | 说明 |
|------|------|
| 文档版本 | v0.1 |
| 编制日期 | 2026-05-13 |
| 适用代码 | `apps/web/src/` React + TypeScript + Tailwind 前端 |
| 目标 | 为全部前端模块提供统一视觉、布局、组件和交互规范 |
| 配套文档 | `Banking_Budget_UI_Unified_PDD.md`、`Banking_Budget_System_PDD.md`、`Banking_Budget_Agent_PDD.md` |

---

## 1. 总原则

本系统是银行预算和经营分析工具，不是营销官网。前端统一方向是：高密度、低噪音、强层级、可追溯、适合长时间录入和复核。

所有模块改造必须遵守：

- 当前前端唯一运行入口是 `apps/web/src/`；根目录旧 `src/`、`src_from_Figma/` 和根目录前端配置只属于历史归档语境，不得按本规范重建为当前业务入口。
- 页面直接进入工作状态，不做大面积欢迎页、宣传文案或装饰图。
- 默认使用白色工作区、浅灰页面底、细边框、紧凑控件。
- 表格和树表是主表达方式，卡片只用于摘要、待确认项、批次、质量报告等独立对象。
- AI 相关内容必须能确认、能追踪、能解释，不和正式业务结果混淆。
- 单位、版本、年份、预算/实际口径必须在页面和导出中保持一致。

## 2. 设计 Token

### 2.1 颜色

| Token | 值 | 用途 |
|------|----|------|
| `--bb-bg-app` | `#eef2f6` | 应用外层背景、导航背景基底 |
| `--bb-bg-page` | `#f6f8fb` | 业务页面背景 |
| `--bb-bg-surface` | `#ffffff` | 表格、弹窗、工具栏、卡片 |
| `--bb-bg-subtle` | `#f1f4f8` | 表头、弱区块、只读区域 |
| `--bb-border` | `#d8dee8` | 默认边框 |
| `--bb-border-soft` | `#e8edf4` | 表格内线、弱分隔 |
| `--bb-text-strong` | `#172033` | 标题、重要文本 |
| `--bb-text` | `#334155` | 正文 |
| `--bb-text-muted` | `#64748b` | 辅助信息 |
| `--bb-primary` | `#1d5f9f` | 主操作、选中态 |
| `--bb-primary-hover` | `#164e85` | 主操作 hover |
| `--bb-success` | `#12805c` | 成功、匹配、已完成 |
| `--bb-warning` | `#a15c07` | 警告、待确认、部分成功 |
| `--bb-danger` | `#b42318` | 错误、失败、危险操作 |
| `--bb-ai` | `#5b4b8a` | Agent/AI 建议类内容 |

使用规则：

- 蓝色只用于主操作、选中、链接、焦点，不用于大面积背景。
- 绿色只表示成功或可用，不能表示普通按钮。
- 琥珀色只表示待处理、警告、建设中或部分成功。
- 红色只表示错误、失败或危险操作。
- 紫色只用于 AI/Agent，不扩散到普通预算页面。

### 2.2 字号与行高

| 场景 | 字号 | 行高 |
|------|------|------|
| 全局标题 / 模块标题 | 14px - 16px | 20px - 24px |
| 工具栏、按钮、表单 | 12px | 18px |
| 表格正文 | 12px | 18px |
| 辅助说明、状态文本 | 11px - 12px | 16px - 18px |
| Agent 消息正文 | 12px | 18px - 20px |

规则：

- 不使用随视口缩放的字号。
- 页面内不使用 hero 级大字。
- 数字列使用 `font-variant-numeric: tabular-nums`，右对齐。

### 2.3 间距与尺寸

| Token | 值 | 用途 |
|------|----|------|
| `--bb-space-1` | 4px | 图标间距、小控件内边距 |
| `--bb-space-2` | 8px | 控件间距、表格单元格横向内边距 |
| `--bb-space-3` | 12px | 页面小分组间距 |
| `--bb-space-4` | 16px | 页面外边距、弹窗内容间距 |
| `--bb-radius-sm` | 4px | 输入框、按钮、表格内控件 |
| `--bb-radius` | 6px | 面板、弹窗、卡片 |
| `--bb-control-h` | 30px | 普通按钮和输入框高度 |
| `--bb-row-h` | 32px | 标准表格行高 |
| `--bb-row-h-dense` | 28px | 高密度表格行高 |

## 3. 应用壳层规范

### 3.1 顶栏

顶栏只展示全局上下文：

- 系统名称。
- 软件版本。
- 当前预算年度与版本快照。
- 用户与角色。
- 退出登录。

不得在业务页面重复放置大面积版本信息。业务页面只在筛选栏中放当前业务需要修改的年份、版本、单位。

### 3.2 左侧导航

导航固定为六组：

- 基础数据维护。
- 预算管理。
- 部门费用预算管理模块。
- 多维分析工具。
- 系统配置中心。
- 帮助与使用说明。

规则：

- 一级节点默认展开。
- 叶子节点点击打开标签页。
- 调试入口使用弱强调，只面向管理员。
- 建设中是灰态但可点击；权限不足是不可见或明确无权限，不与建设中混用。

### 3.3 标签页

标签页承载多任务并行。

规则：

- 激活标签使用白底 + 蓝色顶边。
- 非激活标签使用浅灰文字，hover 浅灰背景。
- 超过可见数量进入更多菜单。
- 关闭按钮使用图标，点击区域不小于 20px。

### 3.4 右侧 Agent 面板

右侧面板用于快速澄清、建议和预览，不承载完整报表工作。

规则：

- AI 建议卡使用 `--bb-ai` 弱色系。
- 查询结果表格只做预览，深入分析跳转主工作区。
- 规划确认、透视建议、下一步按钮必须分块展示。

### 3.5 底栏

底栏展示系统可信状态：

- 数据库连接状态。
- 最后全局计算并刷新时间。
- 刷新状态详情弹出层。

底栏不放业务操作按钮。

## 4. 标准页面骨架

全部业务模块使用统一页面结构：

```text
Page
  PageHeader: 标题 / 状态 / 主操作
  PageToolbar: 筛选 / 搜索 / 刷新 / 导入 / 导出
  PageBody: 树表 / 表格 / 报表 / 工作台 / 预览
  PageFeedback: 加载 / 空态 / 错误 / 成功 / 质量报告
```

规则：

- 页面根节点使用 `bb-page`。
- 标题行使用 `bb-page-header`。
- 工具栏使用 `bb-toolbar`。
- 主工作面板使用 `bb-panel`。
- 表格容器使用 `bb-table-wrap`。

## 5. 按钮规范

| Class | 用途 |
|------|------|
| `bb-btn bb-btn-primary` | 保存、生成、导入、查询、下发并试算 |
| `bb-btn bb-btn-secondary` | 刷新、下载模板、预览、复制、打开 |
| `bb-btn bb-btn-success` | 确认成功类操作、下载已生成结果 |
| `bb-btn bb-btn-warning` | 继续处理待确认项 |
| `bb-btn bb-btn-danger` | 删除、覆盖、清空 |
| `bb-icon-btn` | 关闭、展开、刷新、搜索清空等图标按钮 |

规则：

- 同一工具栏最多一个主按钮。
- 危险操作必须二次确认。
- 图标按钮必须提供 `title`。
- 禁用态使用透明度和禁止光标，不改变语义色。

## 6. 表单规范

统一输入控件：

- 文本输入：`bb-input`。
- 下拉框：`bb-select`。
- 多行输入：`bb-textarea`。
- 分段选择：`bb-segmented`。
- 标签说明：`bb-field-label`。

规则：

- 表单标签 11px 或 12px，颜色使用 muted。
- 输入控件高度 30px。
- 筛选栏中的表单不使用大 label，占位和短标签优先。
- 错误信息靠近字段显示，不只在页面顶部显示。

## 7. 表格规范

表格是系统最重要的组件。

### 7.1 基础表格

统一使用：

- `bb-table-wrap`
- `bb-table`
- `bb-cell-number`
- `bb-cell-muted`
- `bb-cell-editable`
- `bb-cell-readonly`
- `bb-cell-locked`
- `bb-cell-error`

规则：

- 表头 sticky。
- 文本左对齐，数字右对齐。
- 行 hover 只用浅灰。
- 边框使用细线，不使用厚重网格。
- 表格内部滚动，不让整页横向滚动。

### 7.2 高密度录入表

适用：

- 机构及产品数据录入。
- 模拟测算情景参数表。
- 费用预测表。

规则：

- 固定识别列。
- 可编辑单元格有白底和聚焦边框。
- 只读对照单元格使用浅灰背景。
- 公式锁定单元格显示锁定态或说明。
- Tab、Enter、方向键行为必须可预测。

### 7.3 报表表格

适用：

- 预算展示报表。
- 费用预算执行报表。
- 透视表。

规则：

- 层级行使用缩进和展开图标。
- 汇总行使用浅色底和更高字重。
- 月度列允许折叠。
- 单位在工具栏和导出文件中一致。

## 8. 树与导航面板规范

适用：

- 左侧导航。
- 产品树。
- 数据科目指标树。
- 预算展示配置行、机构及产品指标体系和机构产品指标运行引用。
- 部门树。
- PPT 缩略图导航。

规则：

- 树容器使用 `bb-tree-pane`。
- 树节点使用 `bb-tree-item`。
- 选中态为浅蓝底和蓝色文字。
- 展开图标位置固定。
- 空树显示可操作空态，不回退前端 mock 数据。

## 9. 卡片与状态块规范

卡片只用于独立对象。

推荐 class：

- `bb-card`
- `bb-stat-card`
- `bb-status-banner`
- `bb-status-banner-success`
- `bb-status-banner-warning`
- `bb-status-banner-danger`
- `bb-ai-card`

规则：

- 页面大区块不要层层卡片化。
- 卡片圆角不超过 8px。
- AI 卡片只能用于智能建议、待确认项、质量检查和 Agent 推荐。

## 10. 弹窗规范

适用：

- Excel 导入。
- 公式编辑器。
- 产品多选。
- 规则配置。
- AI 待确认项。
- 历史记录。

规则：

- 普通弹窗宽度 560px - 720px。
- 表格型弹窗宽度 960px - 1280px。
- 大型配置弹窗可达 90vw / 90vh。
- 标题、内容、页脚分区固定。
- 页脚主按钮在右侧。

## 11. AI 与智能能力规范

适用：

- Agent 助手。
- 智能分析报告。
- 智能演示 PPT。
- 机构及产品指标 AI 配置建议。

规则：

- AI 输出不得直接写入正式计算，必须经过用户采纳、保存草稿、下发确认等路径。
- AI 建议展示置信度、依据、风险或待确认项。
- 低置信度内容进入审核台。
- 生成类功能必须有质量报告。
- 不向用户展示 SQL 原文、原始 JSON 或模型内部提示词。

## 12. 分模块迁移规则

### 12.1 基础数据维护

统一为“树/目录 + 明细表 + 操作栏”。

改造重点：

- 表格统一 `bb-table`。
- 新增/编辑/删除按钮统一按钮层级。
- 空态统一，不使用 mock。
- 产品范围、多选、公式编辑器跨页面复用。

### 12.2 预算管理

统一为“配置 -> 输入 -> 输出”。

改造重点：

- 旧数据科目运行表独立页面已下线；运行口径只在机构及产品指标相关页面和后端运行引用中展示。
- 预算输入和模拟测算情景参数表采用高密度表格规范。
- 模拟测算采用参数区 + 结果区，不做孤立大卡片，也不恢复独立预测驱动输入页。
- 预算展示报表采用报表表格规范。

### 12.3 费用模块

统一为“同步 / 导入 / 录入 / 分析 / 导出”。

改造重点：

- 数据同步管理使用操作卡片，但不包裹整页。
- 导入流程统一 `ImportFlowDialog` 语义。
- 费用预测表和费用执行报表共用筛选栏、单位切换、导出按钮。

### 12.4 多维分析

统一为“字段/筛选设置 + 结果表/图 + 导出”。

改造重点：

- 当前年度透视和多年度透视样式一致。
- 透视图用同一筛选和单位规范。
- Agent 跳转预填后，页面明确显示来源和当前条件。

### 12.5 智能报告 / PPT

统一为“模板/文件 -> AI 识别 -> 绑定/审核 -> 生成 -> 质量报告”。

改造重点：

- 智能报告审核台使用 `bb-ai-card` 和 `bb-table`。
- PPT Template Studio 使用三栏工作台。
- 质量报告统一组件。

### 12.6 系统配置

统一为管理表格和紧凑表单。

改造重点：

- 用户权限管理使用标准表单和表格。
- 系统设定控制不做展示型卡片堆叠。
- Agent 调试入口使用弱化调试样式。

## 13. 验收清单

每个模块改造完成后必须检查：

- 页面是否使用统一标题行和工具栏。
- 主按钮是否唯一且语义正确。
- 表格数字是否右对齐，表头是否固定。
- 加载、空态、错误、成功是否统一。
- 单位、年份、版本、预算/实际口径是否清楚。
- 导出是否跟随当前页面条件。
- AI 内容是否有确认和质量反馈。
- 1366px 宽度下不出现整页横向滚动。
- 1024px 宽度下核心操作可完成。
- `npm run build` 通过。

## 14. 当前前端落地策略

当前 `apps/web/src/app/components` 存在大量页面内 Tailwind 原子类。为了降低风险，采用三步迁移：

1. 先新增全局设计 token 和 `bb-*` 基础 class，让新模块和局部重构有统一语言。
2. 再改全局壳层、导航、标签页、底栏、常用按钮和表格基础样式，快速影响全部模块。
3. 最后逐模块把页面内重复 Tailwind 替换为 `PageShell`、`PageToolbar`、`DataGridShell` 等共享组件。

一次性重写 27 个业务组件风险过高，不作为第一阶段策略。
