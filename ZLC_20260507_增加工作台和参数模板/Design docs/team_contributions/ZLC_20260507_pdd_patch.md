## System PDD 建议新增 (§0.8)

- 本轮将“预算数据输入”模块拆分为两个相邻入口：一是“预测预算工作台”，用于集中查看预测行、驱动项、假设参数与模板绑定关系；二是“预测结果明细台账”，承接原预算基础数据维护的明细录入职责。
- 新增预测预算工作台首版页面后，预算预测流程形成“参数与模板维护 -> 预测工作台绑定 -> 预测结果明细台账录入/校验”的基础闭环，减少配置散落在多个页面的问题。
- 预测预算工作台首版按 `工作簿1.xlsx` 的“开鑫贷 / 小小账户”主线预置预测行，优先覆盖营业收入、利息净收入、净手续费收入、风险成本、平台费率、渠道费、催收、征信、清结算、保险代偿等关键项目。
- 对于系统内暂未沉淀为数据科目的模板驱动项，本轮统一先升级为正式假设参数编码，避免继续依赖一次性手工锚点，便于后续纳入参数目录维护。

> 插入位置：System PDD 的 `## 0.7` 之后，新增 `## 0.8 本轮需求变更（2026-05-07）` 小节。

## Database PDD 建议新增 (§0.X)

- 本轮新增 `forecast_workbench_layout` 表，用于持久化预测预算工作台中的预测行布局信息，包括预测行编码、名称、分组、分类、显示顺序、绑定提示与启停状态。
- 本轮新增 `forecast_line_binding` 表，用于持久化预测行与数据科目、假设参数、规则模板、报表科目之间的绑定关系，支持一个预测行关联多个驱动来源。
- 本轮补充了一组面向“开鑫贷”模板的正式假设参数编码，包括自持日均余额、联贷日均余额、平台费率、保费支出、保险代偿净额等，用于承接暂未标准化为数据科目的预测驱动项。
- 上述新增表与参数的目标是让预测工作台具备可追踪、可维护、可迁移的绑定底座，为后续产品/部门差异化预测配置提供统一存储结构。

## 补充说明

- 本轮涉及后端新接口、数据库自愈建表与前端新页面，部署后需重启前后端服务。
- 由于本轮引入了预测工作台基础表，主合并后需确保 `init_db.py` 在目标环境执行一次，以完成新表与种子初始化。
- 当前“开鑫贷 / 小小账户”预测行仍有部分绑定采用“先沉淀为正式参数，再逐步替换为标准数据科目”的过渡策略，后续可继续按模板逐条细化。
