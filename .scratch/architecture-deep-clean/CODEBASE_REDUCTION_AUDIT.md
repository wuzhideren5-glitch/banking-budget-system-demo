# Codebase Reduction Audit

Date: 2026-05-22

## Current decision

`费用预测逻辑配置` is an active module, not a deletion target. The cleanup direction is:

- Keep the visible page and public API paths.
- Keep `expense_forecast_rule`, `expense_forecast_rule_param`, `expense_forecast_rule_variable`, `expense_forecast_calc_result`, and `expense_forecast_override` as private tables of the 费用 Module.
- Remove duplicate implementation shape by making `apps/api/app/routers/expense_forecast_rules.py` the professional route-registration module and letting `expense_forecast.py` focus on fee forecast table/view/import/export/calculation.

## File classification rules

Future splits must follow the repo layout in `docs/development/repo-layout.md` and the current file map in `docs/product/Banking_Budget_Files.md`.

| File class | Correct location | Rule for future splits |
| --- | --- | --- |
| HTTP interface / route registration | `apps/api/app/routers/` | Keep request/response wiring, auth/permission hooks, and route composition here. Do not place heavy business calculation here. |
| Backend business logic, exports, projections, parsing that is reused by routes | `apps/api/app/services/` | Move calculation, Excel export builders, summary rebuilds, sync logic, and reusable business rules here when the code is more than endpoint glue. |
| Current schema bootstrap, contract checks, seeds, retired-table cleanup | `apps/api/app/db_bootstrap/` | Current table creation and fail-fast schema checks belong here, not inside fat routers. |
| One-off or operator-run maintenance tools | `apps/api/scripts/` | Keep executable current-data maintenance/import scripts here; they must call shared services/bootstrap modules instead of duplicating SQL rules. |
| Frontend screens | `apps/web/src/app/components/` | Page components stay here. Split only when extracting a real sub-view, dialog, grid, or hook used by that page/domain. |
| Frontend API DTOs and client helpers | `apps/web/src/lib/` | Domain API clients can be split here; avoid putting API transport details inside page components. |
| Download templates | `resources/download_template/` | Only checked-in user-download/import templates live here; backups should move out of this active template directory. |
| Agent knowledge / prompt assets | `resources/knowledge_base/` | Semantic dictionaries and generated agent prompt assets live here; business code must not be hidden in knowledge files. |
| Product / architecture docs | `docs/` | PDD, ERD, file map, and architecture decisions live here. |
| Scratch audit / local issues | `.scratch/` | Planning, issue tracker, and cleanup audit state live here; not product runtime source. |
| Runtime data, logs, generated reports | `var/` | Local runtime state only; do not commit generated DB/log/output payloads. |
| Historical delivery packages | `archive/` | Reference and recovery only; never use as active source location. |

The rule of thumb: split by professional responsibility first, then put the new module in the directory that already owns that responsibility. Do not create a new directory just because one file is large.
