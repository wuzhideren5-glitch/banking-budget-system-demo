# 当前节点下行内新增数据科目

Status: ready-for-agent
Category: enhancement
Type: AFK

## Parent

`.scratch/product-dimension-data-account-maintenance/PRD.md`

## What to build

让 **产品维度数据科目视图** 支持在当前选中指标节点下直接新增一行数据科目，而不是通过独立新增弹窗。新行默认继承当前产品或产品线范围，并沿用当前节点的指标绑定上下文。

新增时只要求用户填写少量必填项：**数据科目名称**、**适用范围**、**数值类型**。数据科目代码继续由系统生成，公式和其他可选配置延后到用户显式进入后续配置流程时再补。用户仍可显式修改默认继承的适用范围，包括改成 `全行` 或多产品范围，但这必须是主动选择而不是默认行为。

这个 slice 要把“当前节点下直接新增一条产品相关数据科目”的完整路径打通，并复用现有保存逻辑，不引入新的保存模型。

## Acceptance criteria

- [ ] 用户可在当前选中指标节点下直接新增一行数据科目。
- [ ] 新增行默认继承当前产品或当前产品线范围。
- [ ] 新增行使用当前选中指标节点作为绑定上下文。
- [ ] 新增时只要求填写 `数据科目名称`、`适用范围`、`数值类型` 三个必填项。
- [ ] 数据科目代码继续由系统生成，不要求手工录入。
- [ ] 用户可显式修改默认范围，包括改成 `全行` 或多产品范围。
- [ ] 父级产品线上下文下新增时，默认范围为该父级产品线本身，而不是自动展开所有子产品。
- [ ] 新增结果继续写回现有 **数据科目维护表** 保存链路，不新增平行保存模型。
- [ ] 公式及其他可选配置保留为后续显式配置动作，不阻塞初始新增。
- [ ] 覆盖默认继承范围、范围改写、必填项校验、父级产品线默认值和成功落库的测试或可重复验收。

## Agent Brief

**Category:** enhancement  
**Summary:** Add inline data-account creation under the current indicator-tree node in the product view.

**Current behavior:**  
The product-dimension view can show scoped rows, but users still need a fast way to add missing product-relevant data accounts without leaving context or opening a heavy creation flow.

**Desired behavior:**  
Users create a new row directly under the selected indicator-tree node. The new row inherits the current product or product-line scope by default, requires only name, scope, and value type, and uses system-generated data-account codes. Users may override the default scope, including switching to `全行`, but that must be explicit. The save path continues using the existing data-account persistence model.

**Key interfaces:**  
- Inline new-row UI state  
- Product-scope defaulting logic  
- Indicator-node binding context  
- Existing data-account creation API

**Acceptance criteria:**  
- [ ] Users can add a row inline under the selected node.
- [ ] Default scope follows the current product or product-line context.
- [ ] Required creation fields are limited to name, scope, and value type.
- [ ] Data-account codes remain system-generated.
- [ ] Users can explicitly override scope before save.
- [ ] Parent-product-line creation defaults to the parent line itself.
- [ ] Saving reuses the existing data-account persistence path.

**Out of scope:**  
- Redesigning all save/refresh behavior on the page  
- Replacing the existing formula configuration flow  
- New permissions or approval flows
